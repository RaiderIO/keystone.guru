# Keystone.guru overrides — read these first

Everything below is generated by Boost. **`.claude/CLAUDE.md` — loaded natively by Claude Code as
a separate project instruction file, no import needed — is the authority and wins over anything
inside it.** These are the rules the generated guidance most often gets wrong for this project:

- **Never run PHP, Artisan, PHPUnit or Pest directly on the host machine.** They go through Docker:
  `docker compose exec -T app php artisan ...`, `docker compose exec -T app vendor/bin/phpunit ...`,
  `docker compose exec -T app php artisan test --compact`.
- **`php artisan make:` is safe to use again** — files/folders created via `docker compose exec`
  (including `make:`) land owned as your host user, not root. #3414's `PUID`/`PGID` fix resolved
  this (verified 2026-08-16). A container exec run as root (`docker compose exec -u root ...`)
  still writes root-owned files.
- **This project does not use Vite, and `npm run build` does not exist** — ignore the "Frontend
  Bundling" note below. Assets are built by `scripts/build/build.mjs`; the `package.json` scripts
  are `dev`, `development`, `watch`, `prod`, `production`.
- Useful read-only Artisan tools (host prefix still required):
  `docker compose exec -T app php artisan route:list --except-vendor --path=api`,
  `docker compose exec -T app php artisan config:show database.default`.
- Every new model gets a **repository** (see the `repository-pattern` skill) and a factory. A seeder
  only if the model actually carries seeded data. For APIs use Eloquent API Resources under
  `app/Http/Controllers/Api/V1/` (`api-endpoint` skill). Link to pages with named routes via
  `route()`.
- Tests are PHPUnit (never Pest), built from factories, and run in Docker with
  `docker compose exec -T app php artisan test --compact --filter=<name>`. **Never delete or
  weaken an existing test without approval**, and cover happy paths, failure paths and edge cases.
  The full conventions — base test case, the persistent seeded test DB, `#[Group]`/`#[Test]`
  attributes, naming and cleanup — are in the `writing-tests` skill.
